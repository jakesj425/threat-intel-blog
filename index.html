Two reports today, and they couldn't be more different in scale — one is a browser extension with ~3,600 total users, the other is an RMM zero-day that hands over a technician session without a password. Both are worth your time.

The VPN Go clipboard stealer from Socket is the kind of threat that breaks standard app review. The extension was legitimate for five months. It launched on both stores in December 2025 as a working proxy VPN, then silently added clipboard theft in May 2026 (Chrome) and June 2026 (Firefox). No new install required — just a staged update that added `clipboardRead` permission and a content script polling every 500ms. The Chrome Web Store and Mozilla Add-ons both approved the benign v1.0, and the malicious code arrived months later through the normal update channel. For Firefox especially — 3,499 users — someone's clipboard is feeding 77.91.123.187 right now.

What I find interesting about this one is the proxy functionality was real. Socket confirmed the extensions actually fetched proxy locations, routed traffic, and handled auth. That means users had a genuine reason to keep it installed despite the broken 2.7-star reviews. The staged update pattern with working cover functionality is a well-known mobile malware technique that doesn't get enough attention in the browser extension space. The infrastructure migration from 178.236.252.133 to 77.91.123.187 between versions suggests active maintenance, not a spray-and-pray operation.

The TaskWeaver/Djinn Stealer intrusion is the one that keeps me up. CVE-2026-48558 is an authentication bypass in SimpleHelp's OIDC flow — no user interaction, no phish, no exploit file needed. You just forge an identity token and you're in as a technician. From there, the attacker used SimpleHelp's own file transfer and remote execution to drop TaskWeaver — a 1.08MB Node.js loader with custom basE91 obfuscation, per-scope decoding alphabets, and AES-256-GCM + RSA-2048 hybrid encryption for C2. The loader masquerades as jquery.js and the C2 domain is a.dev-tunnels.com, a typo of Microsoft's legitimate devtunnels.ms.

Source: blackpointcyber.com

The second stage, Djinn Stealer, is what makes this operationally dangerous. It's cross-platform and its collection rules cover cloud credentials for every major provider, AI development assistant tokens for Claude/Gemini/Codex/Cline/opencode (including MCP configs — the local config files that grant AI tools access to repos, databases, and cloud accounts), package registry tokens for npm/PyPI/Maven, cryptocurrency wallets, SSH keys, and /proc//environ on Linux. The encrypted exfiltration means you can see the data leaving but can't read it. Blackpoint's APG had to build a C2 client to recover the payload.

The pattern here isn't new but the execution is clean: compromise a trusted management tool (RMM), use its own capabilities to deploy, maintain a separate encrypted payload channel, and collect credentials that outlive the initial foothold. CISA already added CVE-2026-48558 to KEV after Blackpoint's disclosure. If you run SimpleHelp, patch it yesterday.

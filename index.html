Opinion of a DFIR Guy

TL;DR
  • 7 reports analyzed — 2 Social Engineering & Malvertising, 2 Malware Loaders & Backdoors, 1 Supply Chain Attacks
  • 4 adversarial groups identified
  • 13 CVEs in active use
  • Top report: jscrambler npm Package Compromised in Supply Chain Attack

1. The jscrambler npm compromise is the story that's going to keep me busy this week, and not because it's technically sophisticated — though it is — but because the targeting tells us something about where the threat landscape is heading. A Rust-built infostealer, dropped through a preinstall hook on an npm package with 15,800 weekly downloads, targeting Claude Desktop configs, Cursor MCP settings, Windsurf AI configurations, and opencode. The payload doesn't just grab browser cookies and crypto wallets anymore. It's reading `.claude.json`, `.cursor/mcp.json`, `.codeium/windsurf/mcp_config.json`. The attacker knew exactly who would be installing `jscrambler`: developers working in AI-augmented build pipelines, the exact population whose machines hold the keys to cloud deployments, CI/CD secrets, and increasingly, the configuration that controls their AI coding assistants.

2. The obfuscation is worth noting too. Per-string ChaCha20-Poly1305, 2,400+ encrypted strings, each with its own key and nonce. That's not your average skid operation. Someone took the time to build a proper string encryption layer. The fact that Socket detected it in 6 minutes says more about their detection than the attacker's opsec — the evasion was genuinely good for an npm payload.

3. Lexfo's investigation into the three AiTM operators is some of the best phishing infrastructure analysis I've read this year. Three actors, one exposed Python HTTP server, eighteen months of sustained activity. What stands out to me is the AI-assistance angle: commit metadata shows Claude Haiku 4.5 and Claude Opus 4.6 credited as co-authors on the black-queen Evilginx fork. We've known threat actors use AI for phishing lures and code generation, but this is the first time I've seen generative AI credited in git history for production-grade phishing tooling. The Device Code Flow technique saroula01 uses is particularly nasty — it doesn't phish a password, it abuses Microsoft's own OAuth flow. The victim authenticates on login.microsoftonline.com, a real Microsoft page, and the attacker grabs the token on the backend. MFA is irrelevant. Defenders need to treat Device Code Flow as a high-risk grant type and consider blocking it via Conditional Access unless there's a concrete business need.

4. The WP-SHELLSTORM campaign is a reminder that the webshell business is alive and well. 1.4 million domains, 27 CVEs, 5,700 active webshells. The parallel Nacos campaign was the real find though: 613 configuration files from 11 victims in two days, exposing cloud credentials, database passwords, and Alipay RSA private keys. The actor's own opsec was terrible — FOFA config in an open directory, bash history showing everything — but the toolchain itself was sophisticated. The VShell implant that renames itself to `[kworker/0:2]` to blend into a `ps aux` listing is a nice touch.

Source: socradar.io

5. APT-C-60 continues to refine the same playbook against Japan. The expansion from GitHub/Bitbucket to GitLab, jsDelivr, and Codeberg is interesting but not surprising — they're following the path of least resistance, adding more legitimate services as old ones get burned. The attack chain hasn't fundamentally changed: LNK in a RAR, mshta.exe executing JavaScript, git.exe running scripts. It works, so they keep doing it. JPCERT's consistent documentation of this group over three years is the kind of patient tracking that makes CTI useful.

Source: blogs.jpcert.or.jp

6. On the APT37 side, Operation Capsule Vault is a reminder that targeted attacks don't need novel exploits — they need good pretext. An academic conference lure about "Why Wonsan-Kalma Tourism Now?" aimed at policy researchers, using a PIF file disguised as a PDF inside an ISO. The EMBED_PAYLOAD_v2 structure that shows a legitimate PDF while executing shellcode in memory is elegant. Cloud C2 via pCloud, Dropbox, and Yandex makes infrastructure takedown nearly impossible — you're not taking down Dropbox because of one APT campaign.

Source: genians.co.kr

7. The Huntress SQLi writeup and the Stormshield DocuSign RMM piece round out the week with the kind of bread-and-butter DFIR analysis that keeps things grounded. The Huntress case is notable for the breadth of post-compromise modifications: BadIIS modules, XMRig miner, CnCrypt, new admin accounts, RDP enablement. Not a sophisticated attack, but thorough. The Stormshield piece adds another data point to the "legitimate RMM tools as backdoors" trend. At this point, if you see Atera, ScreenConnect, or SimpleHelp being installed on a machine without a clear support ticket, that's a SOC escalation.

8. If there's one detection configuration change I'd make this week: add a Conditional Access policy to block Device Code Flow for all users except those with a documented exemption. And if you're running an npm-driven build pipeline, check your lockfiles for jscrambler 8.14.0, 8.16.0, 8.17.0, 8.18.0, or 8.20.0. The clean version is 8.22.0.

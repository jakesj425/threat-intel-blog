    Opinion of a DFIR Guy

    1. Inside a TrickBot Variant Using DNS Tunneling for C2

    This TrickBot variant (not to be confused with the original botnet still operated by UNC1878) is a standalone fork that swaps HTTP for DNS tunneling over TXT and A records. The evasion is notable — it registers as a Wireshark auto-update service and uses Nslookup to exfil data. DNS tunneling is noisy if you know what to look for: abnormally long TXT queries, high query volume to a single domain, and base64-encoded subdomains. If you don't have DNS query logging at the edge, this variant will fly right under the radar.

    Source: fortinet.com

    2. Dolphin X Stealer Targets 300+ Apps and Profiles Users with AI

    A MaaS stealer that's aggressively pushing the envelope on victim profiling. Dolphin X uses AI-powered data filtering — it scans for high-value targets by scraping sensitive files, browser profiles, and over 300 application configurations, then exfiltrates only what matters. The server-side build system lets operators customize the payload per target. What stands out here is the automation: the malware decides who's worth stealing from, not the operator. Defenders should monitor for unusual browser profile access and outbound HTTPS to unknown endpoints, especially from non-browser processes.

    Source: varonis.com

    3. Abusing Trusted Business Workflows: A Multi-Stage Phantom Stealer Campaign

    A multi-stage campaign from a threat actor likely focused on Southeast Asian targets. Phantom Stealer v3.5.0 uses UPS and LHDN-themed phishing lures to deliver a payload that progresses through AES-encrypted —> XOR —> reflective .NET loading before establishing SMTP exfiltration. The evolution to v3.5.0 suggests active development. The phishing angles are convincing to anyone who deals with logistics or tax authorities. Email gateway policies blocking archive-to-exe chains and monitoring for .NET reflection load would catch this at stages 2 or 3.

    Source: seqrite.com

    4. Detecting the Klue supply chain attack in Salesforce instances

    The Klue supply chain attack demonstrates how third-party risk cascades in SaaS ecosystems. The Icarus group exploited a dormant service account in a Klue integration — a credential that should have been rotated or revoked — to steal OAuth tokens and escalate privileges across Salesforce instances. This is the kind of attack that bypasses all your security controls because it originates from a trusted integration. The lesson: audit unused API credentials aggressively, enforce OAuth token binding, and treat every integration as a potential pivot point.

    Source: securitylabs.datadoghq.com

    5. An unknown actor distributes malicious VBS scripts via WhatsApp

    A social engineering campaign using compromised WhatsApp accounts to distribute VBScript droppers that ultimately deliver ValleyRAT. The attack chain is deceptively simple: the victim receives a message from a trusted contact -> clicks a link -> a VBS script downloads -> ValleyRAT deploys with RMM-like capabilities for persistent access. ValleyRAT has been connected to a Chinese-speaking APT group in prior reporting. The WhatsApp vector is effective because it weaponizes trust — the message comes from someone the victim knows. User education needs to cover messaging apps, not just email.

    Source: securelist.com

Opinion of a DFIR Guy

The GigaWiper analysis from Microsoft is the most technically interesting thing I read today, and not for the reasons you might think. It's not that the malware is sophisticated — the RC4+CBC layered encryption and RabbitMQ-over-AMQP C2 are competent but not groundbreaking. What's interesting is that GigaWiper is basically a malware merge commit. The backdoor embeds three previously separate families — Crucio ransomware, FlockWiper, and a standalone disk wiper — as internal commands. Command 1 calls the wiper, command 3 triggers a fake-ransomware file encryptor that never saves the key, command 12 does multi-pass secure wiping. The actor didn't write new malware; they ran `git merge` on their existing toolset and added a RabbitMQ control plane on top.

That pattern matters because it's not unique. GodDamn ransomware (Hyadina's third iteration after Monster and Beast) follows the same playbook — same PoisonX kernel driver, same AnyDesk + NirSoft toolkit, same 4-day dwell. These groups aren't evolving their capabilities, they're standardizing their supply chain. The tooling is becoming interchangeable. When a ransomware op uses the same credential harvester as an espionage group, attribution based on tool hashes alone becomes nearly useless.

The SentinelOne report on Pakistani law enforcement is a good reminder that attribution should focus on strategic motive, not just TTPs. Both China-nexus and India-nexus groups hit Balochistan Police, but from opposite directions. China wants to independently assess threats to its nationals after Pakistan failed to prevent repeated attacks. India wants visibility into a province central to their adversarial relationship. Same target, same data sets, completely different intelligence requirements. The weaponization of the Complaint Management System is the detail that stood out — the implants were disguised as a portal update (`cms_plugin.exe`) and displayed "Update Complete! Please refresh the page" on execution. That's targeted, patient, and operationally secure. Whoever deployed those implants had access to the web server and understood exactly who the users were.

The Injective SDK npm compromise is frustrating because it was entirely preventable and almost immediately contained, yet the malicious version is still downloadable. Socket's analysis shows the compromise lasted about three hours on June 8, but npm has only deprecated the package, not removed it. The exfiltration technique was clean — base64-encoded POST requests to legitimate Injective infrastructure endpoints (`testnet.archival.chain.grpc-web.injective.network`), blending malicious traffic with normal API calls. 310 downloads in three hours is relatively small, but the 50,000 weekly download count of the clean package means the blast radius through transitive dependencies is much larger. This is the third significant npm supply chain incident this month alone (following Miasma Mini Shai-Hulud and the Mastra compromise). The ecosystem's response is still too slow.

The Albiriox campaign from D3Lab shows how Android malware delivery has matured. The dropper is self-contained — the second stage is AES-CBC encrypted and GZIP compressed inside image assets within the APK itself. No network download required at deployment. The Telegram bot delivery channel with a referral bonus (100 USD for installing, 50 for referring a friend) is basically a mobile malware affiliate program. The raw TCP protocol with 4-byte big-endian length framing on port 5555 matches known Albiriox samples and the developer's own Telegram channel screenshots. If you see outbound TCP on port 5555 from an Android device, investigate immediately.

The Vercel abuse campaign from CyberArmor is the least technically sophisticated but the most broadly relevant. 28 campaigns, 1,271 users targeted, using the same playbook — phishing email → Vercel-hosted fake Adobe PDF page → Invoice06092025.exe.bin → LogMeIn installation. The attackers are using Vercel's free tier as their phishing infrastructure. No domain registration needed, no hosting bills, no abuse reports that get taken seriously quickly. Vercel's `.vercel.app` subdomains are treated as trusted by URL scanners, and the 28 distinct campaign hostnames suggest they're iterating faster than blocklists can keep up. For defenders: block `.vercel.app` domains in email if your organization doesn't use Vercel, or at minimum apply extra scrutiny. The signal-to-noise ratio on Vercel-hosted phishing is terrible right now.

What ties today's reports together is that every single one involves an attacker using a trusted platform against its intended purpose — Vercel for phishing, npm for supply chain attacks, Telegram for malware delivery, legitimate remote access tools for persistence, RabbitMQ/Redis for C2, Microsoft-signed kernel drivers for defense evasion. We're past the point where trusting a platform because it's legitimately managed is sufficient. The attack surface isn't the vulnerability; it's the trust model.
